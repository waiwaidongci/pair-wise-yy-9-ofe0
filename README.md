# 古法蓝晒底片整理室

运行：

```bash
npm start
```

访问 `http://localhost:3040`。

## 模块划分

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 业务规则 | `lib/rackRules.js` | 底片编号唯一、晒架占用判定、光照曝光补偿、药液/尺寸复验、参数失效状态机（纯函数，不落库） |
| 存储 | `lib/rackStore.js` | 晒架/药液批次/晒程持久化，写操作经 `withLock` 串行化，防并发重复落库 |
| 页面 | `lib/rackPage.js` | `/racks` 晒架管理页（建程、改参、换架、复验、完成、药液启停） |

`server.js` 只做 HTTP 路由与模块装配；原底片整理页 `/` 与底片数据保持不变。

## 数据文件

- `data/cyanotype-negative-room.json` —— 底片数据（原有，结构不变）
- `data/cyanotype-rack-room.json` —— 晒架模块数据（首次访问自动播种：4 个晒架、3 个药液批次）

刷新/重启后两个文件各自持久化，页面与存储一致。

## 晒架模块规则

- 每张底片按编号唯一；建档重复编号返回 `409`。
- 同一晒架在一个开放晒程内只接一张底片；并发重复建程恰好一个成功，其余 `409` 且不落库（写操作全局加锁）。
- 同一底片已有开放晒程时再建返回 `409`。
- 建程必须登记光照、药液批次、玻璃板尺寸；曝光时间按底片基准曝光 × 光照档位补偿（烈日 0.85 / 薄云 1.0 / 厚云 1.25 / 阴天 1.4）。
- 药液停用（或未登记）、玻璃板尺寸与底片不符、缺基准曝光 → 只进「待复验」，**不占晒架**。
- 晒程后修改光照/药液/尺寸 → 曝光结论失效，退回「待复验」并释放晒架；换晒架先重查目标占用，被占返回 `409`，成功也退回待复验。
- 待复验晒程复验通过才重新占用晒架、结论恢复有效；完成晒程释放晒架。

## 主要接口

- `GET /racks`、`GET /api/rack-room`
- `POST /api/sessions`（建程，冲突 409）
- `PATCH /api/sessions/:id`（改参数）
- `POST /api/sessions/:id/rack`（换晒架）、`/recheck`（复验）、`/close`（完成）
- `PATCH /api/chemical-batches/:code`（启用/停用药液批次）
