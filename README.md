# 古法蓝晒底片整理室

运行：

```bash
npm start
```

访问 `http://localhost:3040`。数据保存在 `data/cyanotype-negative-room.json`。

## 模块划分

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 存储 | `rack/storage.js` | JSON 持久化、旧数据兼容迁移、串行写入队列（并发建程原子性） |
| 业务规则 | `rack/rules.js` | 底片唯一性、晒架占用、曝光补偿、待复验判定、改参失效 |
| 页面 | `rack/view.js` | 底片整理室页（保留）与晒架占用/曝光补偿页（新增） |
| HTTP 路由 | `server.js` | 纤薄路由层，不含业务判断 |

- 底片整理室（原有页面/接口/数据保持不变）：`/`、`/api/...`
- 晒架占用与曝光补偿（新模块）：`/rack`、`/rack/api/...`

## 晒架与曝光补偿规则

- 每张底片按编号唯一；同一晒架在一个开放晒程内只接一张底片；同一底片也只能在一个开放晒程内。
- 重复/并发建程返回 **409 且不落库**（串行写入队列保证判定与写入原子）。
- 建程登记光照、药液批次、玻璃板尺寸，按基准曝光补偿：
  `补偿秒数 = 基准 × 60 ÷ 光照系数 × 药液系数`（取整到 5 秒）。
- 药液批次停用/不存在、或玻璃板尺寸与晒架不匹配：只进 **待复验**，不占用晒架。
- 晒程完成后释放晒架并登记结论；之后修改光照/药液/尺寸/晒架/基准参数会使结论失效并退回待复验。
- 换晒架会重新检查占用；待复验需复验通过后才占用晒架。

数据文件首次启动时自动迁移：原有 `items` 原样保留，仅新增 `racks`、`batches`、`sessions`、`rackSettings`。
